## Prompt queue (2026-10-31, D47)
- **What:** line up prompts for a session; each is typed in when the turn before it finishes. Side panel > **Queue** tab, chip on cards (`data-queue-chip`).
- **Main:** `main/queue/promptQueue.ts` subscribes to the runtime registry. On an activity transition to `finished` (running, awake, not Shell, not closed) it pops the first `Session.queue` item, saves the rest, writes the text through `controller.writeToPty`, and writes `

A per-session guard (cleared by working / needs-input / stop, or after 30 s) stops a second send before the new turn starts. `session:setQueue` re-checks at once (idle session → immediate send); `session:sendQueuedNow` types one item immediately. Wired in `index.ts`, stopped in shutdown.
- **Store:** `validateQueue` / `setSessionQueue` (`store/sessionNotes.ts`), invalid stored queues are dropped (persistence never fails the file for it).

## Bell escalation: repeat the alert while unread (2026-10-27, D44)
- **Setting.** `reminder { enabled: true, afterMinutes: 10 }` (1–120 minutes) is store-backed and lives on Settings > **Sound** (`ReminderBlock.tsx`), not localStorage, because main reads it on every tick. Turning it off stops all repeats immediately and survives a restart.
- **Pure bookkeeping.** `main/attention/reminder.ts` holds `since` / `lastRemindAt`, the due check (once per interval), the 1..120 clamp and the rules: `unread` never schedules; clearing/forgetting disarms; a priority upgrade keeps `since` but re-arms the repeat. Unit tests `reminder.test.ts` (12) + service tests in `AttentionService.test.ts`.
- **One timer in the service.** `AttentionService` arms on every non-null transition and disarms on null/forget. A 30 s interval started in `start()` (cleared in `stop()`) reads `getReminderSettings()` each tick, so changes apply live. A due id gets the same `Notifier.notify` (sound event + taskbar flash, 1500 ms debounce intact) and `onReminder`; `index.ts` reuses `attentionNotice` and `notifier.notifySession` for the desktop text. The main process still never plays audio.
- **On-screen sessions stay silent.** A due reminder for the session on screen is marked as snoozed (no sound/flash/notice); leaving it starts a fresh interval. Sleeping keeps the reminder (the bell is kept), reading/clearing/closing/removing disarms it. Restart v1: the wait start is in memory, so a pre-restart bell stays silent until a new raise.
- **E2E:** `npm run e2e:reminder` (17 checks, ~2.5 minutes: real Settings > Sound input stores 1 minute; a background hook bell pings at once and repeats after ~60 s with the same reason; an on-screen bell never sounds; clearing stops the repeat; the UI switch turns it off and a new bell pings only once). `docs/LESSONS.md` notes why the Notifier's clock must be injected in tests.

## Bulk session actions (2026-10-26, D42)
- **Selection is pure and shared.** `renderer/state/multiSelect.ts` holds the click-mode rules (`selectOnly` / `toggleSelection` / `selectRange` / `pruneSelection` / `orderedSelection`, 25 unit tests) and `useMultiSelect.ts` wires them to React: it prunes ids that leave the visible order, exposes `selectedIds` **in view order**, and clears on `Esc` (window listener; skipped while a dialog/menu is open or focus is in an input/xterm).
- **Clicks.** Plain click still opens the session and clears the bulk ids (it only sets the range anchor). Ctrl/Cmd+click toggles without opening; Shift+click replaces the selection with the visible range from the anchor. If the bulk set is empty, Ctrl+click first seeds the plain-clicked anchor, so "open one, Ctrl+click another" gives the expected two (Explorer behaviour).
- **Sidebar.** `Sidebar.tsx` owns the selection (order = `flatSessionIds`) and renders `components/BulkActionBar.tsx` above the footer: Sleep / Wake / Set status / Move to group / Clear. Actions run sequentially in view order with a per-item try/catch, so one failure still reports through the store banner and the rest proceed; the selection is deliberately kept after an action. Sleep uses `window.api.sleepSession`; Wake opens the session (there is no renderer `wakeSession`); Move appends to the target group with a locally advancing index.
- **Hub.** `HubView.tsx` uses the same hook over board order (No status column, then status columns, activity order) and the same bar; `ModeWorkspace` passes `onSleepSession` / `onMoveSession`. Sidebar and Hub selections are independent.
- **Scope.** Closed sessions are never selected (they are not in `flatSessionIds`/board order); the Hub has no "Close" action. Verified by `e2e:bulk` (18 checks: real Ctrl/Shift clicks, active tab unchanged, Esc, bulk sleep with Sleep disabled/Wake enabled, status and group menus, DnD regression, Hub parity).

## Usage bars for both agents (2026-10-25, D37)
- **Two provider groups.** `UsageState.accounts` is the display list (Claude first, then `opencode-go`); `UsageState.account` stays the Claude account and is still the ONLY input of the autopilot, quota guard and toasts (D30 untouched). `AccountUsage` gained `provider?` (absent = claude, so old data still reads) and `monthly?` (Go only). Main omits `accounts` when it is empty, which keeps the legacy `{account,sessions}` shape for Claude-only users.
- **Where the Go numbers come from.** The OpenCode plugin resolves the Go credential through the v2 API (`context.integration.connection.active('opencode-go')` -> `resolve()`, `CredentialValue` `{type:'key'|'oauth'}`), GETs `https://opencode.ai/zen/go/v1/usage`, maps rolling/weekly/monthly to five_hour/seven_day/monthly and POSTs a normal statusline body with `source: 'opencode-go'` to the existing hook endpoint. Called at setup (forced) and after each turn end, throttled to once per 5 minutes (`PLUGIN_GO_USAGE_THROTTLE_MS`), with an in-flight guard. The key never leaves the plugin process and is never posted or logged; non-2xx, offline, no login or no usable window posts NOTHING (stale/absent bars, never fake ones).
- **Status bar.** `UsageChips` renders one group per account: `data-account="claude"` / `"opencode-go"`, provider labels only when two or more groups exist, a `Month` chip for Go, stale opacity per account. Waiting text is now "Usage: waiting for a turn" (it used to name Claude even when the Go group existed). Groups come from `accountsForDisplay()` so a legacy state (no list) still renders one Claude group.
- **Merge + cache.** `mergeUsageState` merges per provider: a fresh row always replaces its cached one, a missing Claude row keeps the cached value (main restarts empty and only learns plan usage from the next turn), and a missing Go row is DROPPED (that is how the main-side toggle takes effect). The localStorage cache (`sessiondeck.usage.v1`) is now an array (`parseCachedAccounts`/`serializeAccounts`); a legacy single object still parses as one Claude row. What the bar shows is what gets persisted, so a provider main does not know yet survives a reload.
- **Settings.** `QuotaSettings.showOpencodeGo` (default true), Settings > Quota "Show OpenCode Go usage". Main enforces it: `featureWiring` subscribes to the store, calls `usage.setOpencodeGoEnabled(...)` (and once at boot) and unsubscribes on shutdown; the renderer ALSO filters Go by the setting, so the bars disappear immediately. Re-enabling shows nothing until fresh Go data arrives.

## Store durability and config merge (2026-10-25)
- **A read error is no longer "corrupt".** `store/persistence.ts` only renames the file and starts empty when the JSON or its shape is invalid. A locked/unreadable file (EPERM/EBUSY/EIO) now aborts startup with an error box and leaves the file untouched, so no empty store is ever saved over it. A successful load keeps a best-effort copy at `<userData>/sessiondeck-store.json.bak`.
- **Saves are serialized and use a unique temp file** (`<path>.<pid>.<uuid>.tmp`): a debounce-timer write and a `flush()` can no longer race on one `.tmp` path. The queue keeps working after a failed write; timer failures are logged, `flush()` rejects to its caller.
- **OpenCode config is merged, not replaced.** `OPENCODE_CONFIG_CONTENT` now joins the user's own value (plugins appended, `permission: {"*": "allow"}` merged, model/provider/other fields kept). An unparseable value is left alone instead of being overwritten.
- **Hardening:** HookServer drains an oversized body instead of letting it back up; `will-navigate` compares origin/path/query (`app/navigation.ts`) rather than a string prefix.
- **Tests:** new `pluginEnv.test.ts` and `navigation.test.ts`; persistence now covers the .bak copy, a non-corruption read error, overlapping saves and a failed save. The bash/curl hook test gets a 20 s timeout and reports a real SKIP when the tools are absent (it used to hang or silently pass).

Persisted in `<userData>/sessiondeck-timeline.json` (200 turns/session, 30 days, a turn open at quit comes back 'exited'; sleep times are saved too, see below).
- Out-of-order hooks (hardening W1): a prompt submitted while the previous turn is still open SUPERSEDES it (`supersedeRunningTurn`: ended 'finished' now, queued in `awaitingStop`, FIFO, max 8). A late Stop settles the OLDEST superseded turn, not the one just started; after it the cost cursor moves to the next queued turn (else the running one). `CostTrack.startCost` is a cursor advanced on every `refreshCost`, so cost increments accumulate per targeted turn and a late statusLine books its delta on the old turn. Sleep records live in the timeline file (`sleeps: [{sessionId, at}]`, newest per session, retention-pruned) so `lastSleptAt` survives a restart for the away summary.
- Away: `app/userPresence.ts` sees the user come back (same input signal as sleep-all: key/click/wheel IPC + pty writes) after `away.afterMinutes` (default 15, Settings > General); `timeline/awaySummary.ts` builds the summary; sent as `ev:awaySummary` only when something happened; `away:getLast` keeps the last one.
- Renderer: side panel tabs Notes | Activity (`timeline/ActivityList`), `AwayDialog` (rows open the session), palette action 'Show "While you were away"'.
- E2E: `scripts/e2e-away.cjs` (16 checks, ~2 min: real hook/statusLine requests, real 1-minute absence with key presses, an out-of-order late Stop/late cost pair, restart keeps the timeline).

## Quota autopilot (D30)
- At the critical level of EITHER plan window (5-hour or weekly) the guard alert passes `autopilot.onAlert`: Settings > Quota "At the critical level" = ask (toast button "Sleep N idle sessions") / sleep automatically / nothing. Idle = open, running, not working or needs-input, not Keep awake, not Remote Control; busy turns are never interrupted. A weekly critical sleeps the idle sessions until the next five-hour reset (there are no 7-day holds); a weekly RESET is notification-only and is never swallowed by the 5-hour reset dedup (it does not touch the autopilot state).
- Held sessions (slept for quota, or a Claude turn cut off by the usage-limit message) are stored in `<userData>/quota-autopilot.json` with the reset time. The autopilot has its OWN timer at resets_at + 5 s (no usage update arrives while everything sleeps); a later guard reset alert for the same reset is dropped (30 min dedup, five-hour resets only). "When the 5-hour window resets" = ask (toast "Wake N sessions" + "Type continue" checkbox) / wake automatically. Waking resumes in the background (`controller.wakeSession`), the screen stays put. "continue" is typed only into limit-stopped sessions, after their output has been quiet for 3 s.
- Limit detection: `outputSignals.ts` USAGE_LIMIT_PATTERNS, Claude only, armed only by a prompt submitted in the running process (a resumed session redrawing an old message is ignored). The first real match of a process is written to `main-errors.log` as `usage limit wording (add to USAGE_LIMIT_PATTERNS if new)` so the list can grow from actual wording; the log holds one snippet per process, only when a limit was really reported.
- Status bar chip "N waiting for reset · HH:MM" wakes them on click.
- E2E: `scripts/e2e-autopilot.cjs` (17 checks, ~3 min, fake usage through the statusLine endpoint, idle OpenCode sessions so no real usage interferes).
- Review (deepseek-v4-pro, read-only) findings fixed: "continue" never reached a limit-stopped session that kept running (now its quiet timer starts at once); quota IPC waits for the state file to load. The three timeline gaps found in that review (late Stop, late cost, sleeps lost on restart) are fixed in the Timeline section above (hardening W1).

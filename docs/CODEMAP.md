# Code map

Where things live. One line per folder, plus the files you usually need. Feature details (rules, code path, tests per feature) are in `docs/FEATURES.md`; how to build a change is in `docs/IMPLEMENTATION.md`. Tests sit next to the code as `*.test.ts`.

## Docs
- `CLAUDE.md` / `AGENTS.md`: entry points for agents (read-first list, standing rules).
- `HANDOFF.md`: one-page current state, known gaps, history.
- `docs/DECISIONS.md`: the user's decisions (Dnn) and working rules (Wnn).
- `docs/FEATURES.md`: feature tree, per-domain matrices, cross-cutting maps (IPC, storage, shortcuts, settings, e2e), invariants, gaps.
- `docs/IMPLEMENTATION.md`: the implementation standard (workflow, architecture rules, checklists, tests, definition of done).
- `docs/CODEMAP.md`: this file. `docs/LESSONS.md`: gotchas by topic.
- `DESIGN.md`: the Orca look. `README.md`: features, run, test. `PLAN.md`: the original v1 plan (historical).

## Contract (main <-> renderer), change additively and on purpose
- `src/shared/types.ts`: every shared shape (Session, RuntimeState, AppSettings + defaults, usage, workers).
- `src/shared/ipc.ts`: channel names (`IPC.*`) and the `Api` interface the renderer sees as `window.api`.
- `src/shared/jarvisSchedule.ts`: how a Jarvis schedule is written ("09:00 weekdays"), shared by main and renderer (D54).
- `src/shared/reviewComments.ts`: the review-comment prompt (Changes panel Send and Jarvis `send_review_comments`).
- `src/shared/idleReminder.ts`: `isIdleReminder` (Claude's "waiting for your input" Notification), used by main and the renderer's attention sort (D61).
- `src/shared/guards.ts`: tiny runtime helpers used by main and renderer (`isRecord`, `errorMessage`). Use these instead of local copies.
- `src/preload/index.ts`: implements `window.api` with `ipcRenderer`.

## Main process (`src/main/`)
- `index.ts`: startup wiring (window registry: main + popped-out Code window, events broadcast to both). Creates store, pty, attention, runtime, controller, schedulers, tray, IPC; shutdown order.
- `app/`: the core. `codeWiring.ts` (Code mode IPC: repos, worktrees, changes, diffs; pushes ev:worktreeChanges), `codeGitOps.ts` + `codeGitValidation.ts` (D60: commit / push / PR / merge / delete from disk, shared by the IPC and Jarvis), `windowRegistry.ts` + `activeSessions.ts` (two windows, session on screen per window), `featureWiring.ts` (connects timeline, away summary and quota autopilot to store/runtime/usage/IPC), `userPresence.ts` (away detection from user input), `sessionController.ts` (start/close/reopen/sleep/hook events), `runtimeRegistry.ts` (live per-session state: run, attention, activity, sleeping), `ipcHandlers.ts` + `ipcValidation.ts` + `settingsValidation.ts` (every IPC entry is validated here), `startOptions.ts` / `claudeLaunch.ts` (how `claude` / `opencode` are launched — OpenCode sessions run `opencode --standalone [-s <id>]`, the model goes into the config content), `transcript.ts` (resume checks), `outputSignals.ts` (Remote Control and spinner read off the screen), `trustPrompt.ts` (opt-in detection/answer of Claude's folder-trust menu), `window.ts`, `trayWiring.ts`, `closeToTray.ts`, `loginItem.ts`, `paths.ts`, `errorLog.ts`, `navigation.ts` (same-document check for `will-navigate`).
- `store/`: persisted data (`presets.ts`: saved New Session forms, D49). `SessionStore.ts`, `reducers.ts` (pure updates), `codeReducers.ts` + `codePersistence.ts` (repos, worktrees), `persistence.ts` (load/save, drops invalid values), `settings.ts` (settings validation), `sessionNotes.ts`.
- `pty/`: terminals. `PtyManager.ts` (node-pty ConPTY), `RingBuffer.ts` (replay, O(1) append; PtyManager batches output per session before it), `treeKiller.ts` (kills the whole process tree), `launch.ts`.
- `attention/`: who needs the user. `HookServer.ts` (local HTTP server for Claude hooks, statusLine, worker events; token-checked), `claudeSettings.ts` (the private `--settings` file), `AttentionManager.ts` (reasons + priority), `AttentionService.ts` (single transition point + the 30 s reminder timer), `reminder.ts` (pure reminder bookkeeping: since / lastRemindAt / due), `Notifier.ts`, `IdleDetector.ts`.
- `automation/`: auto status from hook activity.
- `sleep/`: `sleepPolicy.ts` (per-session idle rule), `sleepAllPolicy.ts` (sleep everything when the app is idle), `SleepScheduler.ts` (30 s tick, user input).
- `quota/`: 80/95% plan alerts (`quotaGuard.ts`), markers file, notices, delivery (`quotaWiring.ts`), and the autopilot (`autopilot.ts` service, `autopilotOps.ts` actions, `autopilotPolicy.ts` pure rules, `autopilotTimer.ts` reset timer, `autopilotContinue.ts` typing "continue", `autopilotStore.ts` state file, `continueFailedNotice.ts` "SessionDeck needs you" text for D33 failures). Hands-off defaults `sleep`/`wake`/`continue` live in `shared/types.ts`, and the one-time old-defaults migration is `store/settings.ts → upgradeLegacyQuotaFields`.
- `usage/`: statusLine parsing, `UsageService.ts`, manual refresh through the OAuth usage endpoint (`oauthUsage.ts`, token stays in main).
- `git/`: Code mode git service, always `execFile('git')`: `repoInfo.ts` (repo root, branches), `branchName.ts` (git-safe names), `worktreeCreate.ts` (`git worktree add -b`), `worktreeChanges.ts` + `worktreeParse.ts` + `untrackedCount.ts` (changes vs merge-base), `worktreeFileDiff.ts` (one file's diff, only for listed paths), `previewRead.ts` (rendered preview of one worktree file: image base64 / markdown text, path resolved + realpath-checked inside the worktree). D60: `commit.ts` (`git status` parse, commit chosen files, index.lock retry), `branchStatus.ts` (remote, upstream, ahead/behind, push, PR defaults), `remoteHost.ts` (remote URL → GitHub/GitLab/Bitbucket new-PR page, pure), `pullRequest.ts` (GitHub CLI check + `gh pr create`), `merge.ts` (merge into base in the repository folder), `worktreeDelete.ts` (removal facts, `git worktree remove` + branch delete).
- `timeline/`: per-session turn log (`timelineService.ts`, `timelineState.ts` pure updates, `timelineFile.ts` persistence) and `awaySummary.ts` (pure "While you were away" builder).
- `app/lastActive.ts`: keeps `Session.lastActiveAt` current (turn start/end, a typed line), throttled per session (D61).
- `app/launchResume.ts`: resume running sessions on launch (D50; `<userData>/resume-on-launch.json`).
- `transcripts/conversationSearch.ts`: read-only search in saved Claude conversations (D52).
- `jarvis/`: Jarvis (D53), the AI session that controls the app. `mcpProtocol.ts` (JSON-RPC tools protocol), `mcpHttpServer.ts` (local POST /mcp, Bearer token), `jarvisTools.ts` (the session tools, undo stack, prompt sender), `appTools.ts` (D55: settings, queue, checklist, groups, statuses, presets, bulk, quota, costs, Code extras, workers), `uiTools.ts` (D55: screen tools, sent to the window), `controlTools.ts` (D58: sounds, sidebar list, Code tree, file on screen, terminal search, tabs, files into a session, links, the app window), `gitTools.ts` (D60: branch status, commit, push, PR, merge), `toolArgs.ts` (argument helpers shared by the tool files), `targets.ts` (name → session/group/status), `screenText.ts` (headless xterm render for read_screen), `jarvisLaunch.ts` (files, launch args, system prompt), `jarvisWiring.ts` (wiring + IPC + Yes/No round trip + schedule delivery), `schedules.ts` (pure schedule rules) + `scheduleService.ts` (schedules.json, 30 s tick), `voice.ts` (Windows speech recognition through PowerShell) (D54).
- `queue/`: the prompt queue (D47). `promptQueue.ts` types the next queued prompt when a session's turn finishes (runtime activity → `finished`), plus Send now.
- `notify/`: desktop notifications. `tray/`: tray icon and menu.
- `links/`: resolves and opens URLs and paths clicked in the terminal. `appLinks.ts` builds the Electron service (used by the IPC handlers and Jarvis's open_link).
- `opencode/`: the plugins injected into OpenCode sessions: `pluginEnv.ts` merges any number of SessionDeck plugin paths into `OPENCODE_CONFIG_CONTENT` (`applyConfigPatch` merges extra top-level keys like `model`; both plugins report their pid as `proc` so the app can tell the owner apart from child workers), `writePlugin.ts` writes the plugin PACKAGE directories (`sessiondeck-opencode-plugin/`, package.json `main` → index.mjs — OpenCode v2 loads configured plugins from package directories only) and removes the legacy single-file plugins. `workers/`: read-only tabs for `opencode` processes started from Claude, Shell or OpenCode sessions (`WorkerHub.ts` with the owner-process handshake, plugin sources).

## Renderer (`src/renderer/`)
- `App.tsx`: window shell (store, usage, mode, focus requests, quota toast; sound and away summary in the main window only).
- `mode/`: Ops | Code (D31). `ModeWorkspace.tsx` (one mode's whole layout, mounted per mode), `useWorkspaceNav.ts` (tabs/split/view per mode), `useWorkspaceCommands.ts` (dialogs, palette, shortcut), `WorkspaceDialogs.tsx`, `ModeTitleBar.tsx` + `ModeSwitch.tsx`, `useUiMode.ts` (stored mode, pop out / dock), `modeLogic.ts` (filter by mode, mode-scoped storage keys).
- `state/`: `useSessionStore.ts` (store + runtime from main, `actions`), `selectors.ts` (grouping, workspaces, filters), `multiSelect.ts` + `useMultiSelect.ts` (bulk-selection rules, shared by the sidebar and the Hub), `useBulkActions.ts` (the bulk Sleep/Wake/Status/Move loops, shared too), `formatTime.ts`, `sessionSort.ts` (D61 pure sort rules) + `useSessionSort.ts` (per-mode sort pref, hover freeze).
- `Sidebar/`: session list, groups, workspaces, status view, Closed section, context menus, New session dialog (`dialogLogic.ts`), `SortMenu.tsx` (the Sort button, also used by the Code sidebar, D61).
- `shell/`: tab bar, status bar, title bar, empty state, tab shortcuts, user-activity reporter.
- `Terminal/`: xterm panes, split workspace, keymap (paste, right click), terminal search (Ctrl+Shift+F), link detection, file drop. D59 right-click menu: `TerminalContextMenu.tsx` (the Radix menu), `useTerminalMenu.ts` (rows + actions on the clicked pane), `terminalMenuLogic.ts` (pure rules), `rightClickPref.ts` (menu or copy/paste setting).
- `split/`: split layout logic. `hub/`: Hub board by status. `notes/`: notes and checklist panel. `queue/`: the side panel Queue tab (`QueuePanel.tsx`, `queueLogic.ts` pure, D47) and the bulk "Send prompt" dialog (`BroadcastDialog.tsx`, D48). `presets/`: session presets (`presetLogic.ts` pure, `PresetMenu.tsx`, D49). `search/`: the Search conversations dialog (D52). `jarvis/`: the right-side Jarvis panel (`JarvisPanel.tsx`, schedule list `JarvisSchedules.tsx`, reading replies aloud `JarvisSpeaker.tsx` (main window), open state `jarvisPanelStore.ts`), pure rules (`jarvisLogic.ts`: width, state text, shortcut), Ctrl+Shift+J (`useJarvisShortcut.ts`), the destructive-action Yes/No (`JarvisConfirm.tsx`) (D53), Jarvis's screen commands (D55: `useJarvisUi.ts` in App, `jarvisUiBridge.ts` registry of the mounted workspace, `workspaceUi.ts` pure action runner; D58: `windowUi.ts` window actions (sounds), `sidebarView.ts` the sidebar list control). `costs/`: cost over time (`costLogic.ts` pure, `CostBars.tsx` chart, `CostDialog.tsx`, `useCostTurns.ts`, D51). `components/BulkActionBar.tsx`: the floating bar shared by the sidebar and the Hub.
- `attention/`: bell icon, Needs you list. `palette/`: command palette (Ctrl+K / Ctrl+Shift+K).
- `code/`: Code mode UI. `sidebar/` (repo > worktree > sessions tree, `codeTree.ts` pure), `dialogs/` (New worktree, New session in a worktree), `changes/` (Changes panel, `parseUnifiedDiff.ts`, `DiffView`, `useWorktreeChanges` + `useWorktreeChangeCounts`, per-line diff comments `annotations.ts` sent to the session via ptyWrite, rich previews: Diff | Preview toggle, `preview.ts` + `PreviewView.tsx` + `MarkdownView.tsx` + `useWorktreeFilePreview.ts`; `changesRequest.ts`: Jarvis opens a file, D58; D60: `GitSection.tsx` (branch line, commit box, result line, confirm/PR dialog), `useGitActions.ts`, `gitActionsLogic.ts` (pure)). `sidebar/RemoveWorktreeDialog.tsx` + `removeWorktreeLogic.ts`: Remove worktree with "delete from disk" (D60).

- `settings/`: Settings dialog and its sections. `sound/`: built-in and custom sounds. `usage/`: usage chips, quota toast with autopilot buttons (`QuotaToast*`, `quotaToastLogic.ts`, `quotaActions.ts`), held-for-reset chip (`QuotaHeldChip`, `useQuotaAutopilot`).

## Scripts (`scripts/`)
- `e2e-lib.cjs`: launches the built app with a temp user-data dir and drives it over CDP (`evaluate`, `send`); `stopOpencodeService()` stops a stale OpenCode background service so cold-spawned children inherit the run's env.
- `run-e2e-detached.cjs`: runs an e2e script DETACHED (`detached: true`, own process group, log `scripts/<name>-last.log`) so an OpenCode server restart in the driving agent's session cannot abort the run; `vitest-full.cjs`: full unit suite via the same launcher.
- `e2e-<feature>.cjs`: one real-app suite per feature (list and purpose in `HANDOFF.md`; many have `npm run e2e:<name>`).
- `smoke-*.cjs`: manual checks with real Claude / OpenCode. `probe-*.cjs`: one-off investigations. `make-icons.cjs`, `patch-node-pty.mjs`: build helpers.

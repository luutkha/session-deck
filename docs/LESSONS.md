# SessionDeck lessons

Things that cost time once. Read the section for the area before touching it. Add an entry when a bug's cause was not obvious (what happened, why, what to do instead). Keep entries in their topic section; dates mark when a lesson was learned.

## Claude Code inside the app
- **Fullscreen UI grabs the mouse.** In `tui: fullscreen`, Claude turns on mouse reporting (`?1000h ?1002h ?1003h ?1006h`) and pastes a reported right-click by itself. Anything SessionDeck does with a mouse button must stop xterm from reporting it (D21, `isRightButton`). Claude may switch fullscreen on by itself, so assume it can be on.
- **Test sessions use the user's real `~/.claude`.** Slash commands persist (`/tui fullscreen` wrote settings.json). For a per-session setting pass `claudeArgs: ['--settings', <temp json file>]`; inline JSON is rejected by the arg validator. A test that must not touch it at all sets `CLAUDE_CONFIG_DIR` to a temp folder (that Claude is then not logged in).
- **Trust prompt per git root.** A folder Claude has not seen as a git root asks "Yes, I trust this folder / No, exit" with **No** preselected.
- **2026-11-01 · Claude Code 2.1.316 drops an Enter that arrives in the same write as an arrow key.** The trust auto-answer wrote Down+Enter as one string: the highlight moved to "Yes", snapped back, and the menu stayed open forever. Send every key as its own write with a pause (`TRUST_ANSWER_KEYS`, 0.5 s then 0.4 s). The same holds for text + Enter (`QUEUE_ENTER_DELAY_MS`).
- **Never send a blind Enter to a starting Claude TUI.** An Enter pressed before the trust dialog rendered was buffered and confirmed "No, exit"; Claude quit and every later write went nowhere. Only press keys on a DETECTED dialog. New Claude versions may also show a "Bypass Permissions" dialog — detect it the same way.
- **Claude TUI replay text is not reliably spaced.** Redraws overlap in the pty replay, and a dialog may appear only as a space-collapsed copy (`Quicksafetycheck:...No,exit`). Collapse whitespace before matching, and check the footer first (`bypasspermissionson`) so dismissed-dialog history is not mistaken for a live dialog.
- **2026-11-01 · Claude's idle reminder is a Notification too.** After about a minute without input Claude sends "Claude is waiting for your input" through the Notification hook, so the activity becomes `needs-input` for an idle session. Anything that types only into `finished` sessions then waits forever (it broke the prompt queue and Jarvis's schedules). Use `activity.isReadyForPrompt` / `isIdleReminder`. Found by a real-Claude e2e; the unit fakes never sent the reminder.
- **Resumed Claude sessions redraw old screen text.** A usage-limit message from an earlier turn can reappear after `--resume`; screen signals that start actions must be armed by a prompt submitted in the running process.
- **A session never prompted has no conversation.** Resuming it fails ("No conversation found", then "already in use"); it gets a fresh Claude id instead (`shouldRotateSessionId`).
- **`NO_COLOR` from the launcher** made sessions monochrome; the pty env strips it. `CLAUDE_CODE_*` / `CLAUDECODE` env from a parent Claude must not leak into sessions; strip them when launching the app from a Claude terminal.
- **`--mcp-config <file>` with `type: "http"` needs no approval and no `~/.claude` change.** The server must answer `initialize` with plain JSON (no event stream needed), notifications with 202 and GET with 405.

## OpenCode
- **`--standalone` exists only on OpenCode v2.x.** v1.x dies/prints help on it. Detect the flag from `opencode --help` (`src/main/opencode/capabilities.ts`), never from the version number; `-s <id>` works on all versions.
- **The TUI CLI has no `--model` flag.** `opencode --standalone --model x/y` prints help and exits ("ShowHelp: Help requested"; a "TUI started" check can pass vacuously on the help text). The model goes into `OPENCODE_CONFIG_CONTENT` as the top-level `model` key; `-s`/`--session` IS valid.
- **A TUI attached to the shared background service never sees per-process env.** Only `--standalone` honors the injected `OPENCODE_CONFIG_CONTENT`. `opencode mcp list` and similar commands also ask the background service, so they report "no servers" for per-process config; test with `opencode run --standalone` instead. `opencode service stop` is best effort (other clients respawn it).
- **Remote MCP servers work through the injected config** (2.1.4): `mcp: { name: { type: 'remote', url, headers, enabled: true } }` plus `instructions: [file]`; `debug config` shows it normalized to `mcp.servers`. The model calls MCP tools through code execution (`tools.sessiondeck.create_group(...)`).
- **The injected config is inherited by child processes.** The parent opencode AND every opencode it spawns load all plugin entries. Identify the parent by the first process that reports (`proc` = pid; the worker plugin posts `hello` first) and filter child events by proc. Reset the owner when the pty starts, not on exit.
- **v2 plugins must be package directories** (`package.json` `main` → `index.mjs`, absolute path, forward slashes); a `file:///...mjs` entry is rejected.
- **v2 (2.1.4) per-turn event order:** `session.inbox.enqueued` (prompt text) → `execution.started` → `instructions.updated` → `inbox.delivered` → `usage.updated` (**cost only**) → `step.started` (model) → deltas → `step.ended` (**tokens**) → `usage.updated` → `execution.succeeded`. No `message.updated` in v2.
- **A plain time throttle can swallow the only useful post.** The cost-only `usage.updated` comes first; let a post through when its model/context differs from the last one.
- **Context % comes from the latest step's prompt tokens** (`input + cache.read + cache.write`), never the cumulative totals; the window size from `context.model.list()` (`limit.context`).
- **Reading a stored provider key:** `context.integration.connection.active(id)` → `resolve()`; `context.credential` only exposes auth flows. No connection = not signed in, post nothing.
- **Costs:** `opencode/<model>` (Zen) bills real money; `opencode/big-pickle` and `*-free` models are free. The Go plan cap is plan-wide and silent in `--format json` mode. A plan cap can hit mid-wave; check `opencode stats --days 1` first, and probe a model with a one-word run before blaming a brief.
- Quoting `--dir "…"` through `cmd /s /c` breaks OpenCode; use the process cwd. `opencode run --pure` disables plugins (invisible to worker tabs).

## Electron / xterm / Windows
- `ready-to-show` did not fire with the hidden title bar; the window is shown explicitly.
- **"On screen" is per window role, and a closed window must clear its role.** Read the union of all roles; clear a role when its window goes away.
- **A pane has exactly ONE host element.** xterm opens into one DOM element for life; a second component rendering its own `TerminalPane` for the same session gets an empty viewport. Render every layout through `TerminalWorkspace` (or one dedicated owner, like the Jarvis panel) and assert `.xterm` has a size.
- **A terminal that hides must not shrink.** `display: none` / width 0 makes xterm fit to a few columns and resizes the pty, so Claude redraws for that width. Slide out with `translate-x-full` + `invisible`.
- **xterm search reports counts only with decorations on**, and one search addon searches one `Terminal`: capture the pane when the bar opens and close the bar on a tab switch.
- **An "ignore the opening click" guard must not sit in `onOpenChange`.** It also swallowed an Escape pressed within 100 ms of a menu opening (D59). Put it in `onPointerDownOutside` only. CDP Escape needs `rawKeyDown`, not `keyDown`.
- **An e2e that right-clicks a terminal must say which right-click it wants** (`sessiondeck.rightclick.v1` = `menu` or `paste`); the default is the menu since D59. A search hit leaves a selection, so the next right-click copies instead of pasting.
- **The terminal draws with WebGL: `.xterm-rows` has no text.** Read terminal content through `window.api.ptyReplay` (or render the replay with `@xterm/headless`, as Jarvis's `read_screen` does); check the canvas size for "is it drawn".
- **2026-11-13 · A hidden xterm must not keep rendering.** Dropping a hidden pane's WebGL context alone made it WORSE (renderer busy 21% -> 37%, 200k DOM nodes): xterm falls back to its DOM renderer, which keeps rewriting rows for every chunk even under `display:none`. Hidden panes now also stop writing (`hiddenQueue.ts`). Chromium allows ~16 WebGL contexts per renderer, past that older panes silently become DOM panes. Measure with `node scripts/bench-sessions.cjs 20 15`.
- **2026-11-13 · One IPC message per pty chunk is the biggest cost with many sessions.** Batch in `PtyManager` BEFORE `RingBuffer.append` so a batch gets one seq (replay and the renderer's SeqGate stay consistent), and flush pending output before exit, restart, kill and replay.
- **2026-11-13 · Without a GPU, xterm WebGL runs on the CPU (SwiftShader).** 20 sessions: ~1,250% CPU, 25 fps. The DOM renderer is the fastest there (our hidden panes do no work, `hiddenQueue.ts`); Canvas is slower than DOM in every measured case. Test with `node scripts/bench-sessions.cjs 20 15 gpu=off` or `gpu=swiftshader`.
- **2026-11-13 · A Windows PC always lists "Microsoft Basic Render Driver" (vendor 0x1414, device 0x8C) next to its real GPUs, none marked `active`.** Classifying from the adapter list called this PC's Intel GPU "software" (and would have turned its GPU process off). Trust `getGPUFeatureStatus()` (`webgl`, `gpu_compositing`) first; use devices only as a tiebreaker. Chromium can also say webgl "enabled" on SwiftShader: only the window can read `UNMASKED_RENDERER_WEBGL`.
- **2026-11-13 · OpenCode runs on free models can edit files and then die (ECONNRESET), hang (exit 124, no output), or even commit by themselves.** Always read `git status`/`git diff`; tell it not to commit. A stale run once re-applied an old brief over finished code and broke the build.
- **`os.tmpdir()` can be an 8.3 short path** (`C:\Users\KHALT_~1\...`); the Claude arg allow-list rejects `~`, so resolve with `fs.realpathSync.native` before passing a temp file as an argument. Git reports the long path, so tests comparing a temp repo path with what the app stored must compare real paths too.
- **Paths with spaces** (a "John Smith" user folder) reach `claude` through `cmd.exe /d /c`; node-pty quotes them correctly. `e2e-spaces.cjs` proves it on the dev build and the packaged exe.
- **2026-11-08 · `git worktree remove` can half-succeed on Windows.** Right after the sessions are stopped, a shell that is still exiting holds the folder: git deletes the files and unregisters the worktree but cannot remove the folder, and the retry says "is not a working tree". `worktreeDelete.ts` then removes the leftover folder only if it is empty, and prunes. Seen 1 run in 2 in `e2e-code-git`; unit tests with a fake reproduce it.
- **Windows 11 accepts `C:\dir\con` as a folder, but git cannot make the branch `con`.** Make every branch SEGMENT safe (`branchNameFor`); test with a real `git worktree add`.
- **The OS clipboard can be dead even though the app runs** (remote/headless sessions), and it comes and goes. Clipboard e2es preflight write+read on every run and report SKIP.
- **Windows speech recognition is available offline** through PowerShell `System.Speech` (installed recognizers only; en-US and zh-CN on the dev PC). It can read a WAV made by `SpeechSynthesizer`, which makes voice testable without a microphone.
- Radix `Slot` forwards `onContextMenu` into child props; components must accept and spread it.
- A hard kill loses localStorage writes Chromium has not committed; e2e restarts use `window.api.quitApp()`.
- electron-builder needs the winCodeSign cache seeded without symlinks (no Developer Mode). In the packaged app a bare `conhost.exe` can outlive a closed session until quit.
- A background job cannot send real OS mouse input; use CDP `Input.dispatchMouseEvent`. CDP screenshots do show the terminal canvas.

## Attention, timeline, quota
- **Attention is recorded for the session on screen; focus only decides pinging** (`AttentionService`, `wireAttentionNotices`). In CDP e2e the window counts as focused.
- **A reminder is a second ordinary raise, so the Notifier debounce applies.** Inject the same clock into the reminder bookkeeping and `Notifier`.
- **A hook can arrive after its turn is over** (Stop and the statusLine cost are separate requests). Keep superseded turns in `awaitingStop` and move the cost cursor only when the previous turn settles; arrival order is not prompt order.
- **A quota reset is invisible while everything sleeps** (no statusLine arrives); the autopilot runs its own timer at `resets_at`.
- **`onAlert` used to return early for every non-five-hour window**, so a weekly critical never acted. The reset path is the only five-hour-only part; the reset dedup is not per window.
- **Limit wording is captured chunk-locally** (the TUI splits it); log once per process, after the `limitArmed` check.
- **Simulating "cut off by the limit" in an e2e:** POST a fake `UserPromptSubmit` hook, then paste the limit phrase; its TUI echo triggers the same screen signal as the real message (`e2e-handsfree`).
- **2026-11-08 · A background `git status` takes `.git/index.lock`.** It refreshes the index opportunistically, so the Changes panel's poll made a Commit at the same moment fail with "Unable to create index.lock: File exists" (found by `e2e-code-git`, never by unit tests). `gitEnv()` sets `GIT_OPTIONAL_LOCKS=0` for every app git call; commands that must lock (add, commit) also retry for ~2 s, since the user's own git can hold the lock.
- **Data that changes outside SessionDeck needs a pull.** Worktree change counts refreshed only on a Claude Stop hook; Shell sessions have no hook. Main broadcasts every changed recompute and the sidebar polls slowly.

## Storage
- **A `readFile` error is not corruption.** Only `JSON.parse` / shape failures may be quarantined; EPERM/EBUSY/EIO stop startup with the file untouched. Keep a `.bak` from the last successful load.
- **Saves race unless serialized.** One in-process chain, a unique temp name per write, and a rename retry on EPERM/EBUSY/EACCES (indexers and AV hold files for a moment).
- **A missing provider in a usage update means two things.** A missing Claude row keeps the cached one (main restarts empty); a missing Go row disappears (the toggle is off). No blanket "keep everything" merge.

## Jarvis and its tools
- **2026-11-08 · Jarvis's tools are built before Code mode's wiring.** `index.ts` hands `code.git` in as a getter; a tool group that read `deps.code.git` when it was created crashed startup ("Cannot access 'code' before initialization"; the unit fakes were plain objects). Read late-wired deps inside `run`, and launch the built app after wiring changes.
- **Reusing a helper with a different purpose bites.** The prompt queue's `canTypeInto` excludes Shell sessions on purpose; Jarvis needs its own `isTypeable`.
- **A woken session is still "sleeping" until its old process exits** (`wakeAfterExit`). After `wakeSession`, wait for a process started after the wake (with a grace period) before typing.
- **A session created in main and focused right away may not be in the renderer's store yet.** `App.requestFocus` keeps the id pending until the store update arrives.
- **Jarvis belongs to no mode.** It is filtered out in `dataForMode` and mounted at the `App` level. Main counts it as always on screen, so its finished turns never ping and it is never auto-slept.
- **A screen command can arrive while the workspace remounts.** `App` mounts one `ModeWorkspace` keyed by mode, so after a mode switch the old handler is gone and the new one registers on mount. `useJarvisUi` waits for the workspace of the wanted mode (`workspaceUiFor`) instead of running against whatever is registered.
- **The side panel reads its tab only on mount.** Changing the stored tab from outside does nothing until `NotesPanel` remounts; Jarvis bumps an epoch in its key.
- **Changing the engine cannot move a conversation.** `openJarvis` replaces a Jarvis whose engine or OpenCode model no longer matches Settings.

## Tests and e2e
- **A `//` comment in a `.css` file breaks only the real build.** An apostrophe in it ("pane's") opens an unterminated string and `@tailwindcss/vite` fails the whole renderer build, while `tsc` and vitest stay green (CSS is not type-checked or imported by tests). Use `/* */` in CSS, and always run `electron-vite build` after an OpenCode session added a stylesheet.
- **A settings row that loads over IPC must start as "Checking...", not as a believable default.** A first paint of "version unknown" looked like a real answer and made an e2e (and a user) read it before the answer arrived.
- **Jarvis tool counts are hardcoded in five e2e scripts** (`e2e-jarvis*.cjs`, `e2e-code-git.cjs`); adding a tool means updating all of them.
- **A wrong CSS import path passes `tsc` and every unit test.** Only the real `electron-vite build` fails (`Could not resolve "../styles/markdown.css"`), and a failed build leaves the OLD `out/` in place, so an e2e then tests the previous build. Build first and read its last lines before trusting an e2e.
- **Click terminal links in an e2e by exact geometry, not by sweeping.** Link resolving is async, so a fast hover sweep sees almost no links. Ask PowerShell for `$Host.UI.RawUI.WindowSize.Height`, use `cellH = .xterm-screen height / rows`, print the targets with a SHORT command (`$f`) after `function prompt { '> ' }; Clear-Host` so the rows are the same with the side panel open or closed (opening it narrows the terminal and wraps long lines), and never click the default prompt line (it holds a folder link that opens Explorer).
- **Test an agent prompt with a fake binary, never the real tool** — `claude.cmd` + a node stub first on PATH before `launchApp`; the stub must `setRawMode(true)` or ESC sequences arrive line-buffered. **But re-check the fake against the real binary after a CLI update** (the trust fake accepted a combined write the real TUI no longer takes).
- **ptyWrite control characters through CDP:** pass REAL control characters in the Node source (`'\x1b[B'`, re-escaped by `JSON.stringify`); a doubly-escaped string reaches the pty as literal text.
- **Two e2e runs on one CDP port silently mix.** `e2e-lib.cjs` refuses a port that already answers; kill the stale tree and check `Get-Process electron` before rerunning. Each suite has its own port.
- **Coordinates lie for off-screen elements.** Hub cards in a scrolled board and controls below a dialog's fold have valid rects outside the viewport; `scrollIntoView` before clicking. The sidebar is an `<aside>` too: select by aria-label or `data-*`.
- **Radix dialogs fade out:** await "closed"; closing returns focus (often to the terminal, where plain Ctrl+K is ignored). Use Ctrl+Shift+K in tests.
- **Desktop conventions need their full click sequence in tests.** Explorer seeds a Ctrl+click selection with the plain-clicked item; unit tests agreed with the wrong rule, the real click sequence exposed it.
- **Fake plan usage needs sessions that report none.** Real Claude sessions overwrite fake numbers through the statusLine; idle OpenCode sessions do not.
- **Judge timing failures carefully.** Real-Claude turns get slower late in a long batch, and the full unit suite running next to e2e suites makes timing tests flaky (`statusLineBash` throttle, `e2e-grid` restart). Rerun a failing real-agent or timing check alone before calling it a regression, and say so. Context-menu checks can flake on a slow machine the same way.
- **A check that only proves "no crash" is not a test of the bug** (the first e2e-paste passed with the bug present). A test that "skips" with an early `return` is a false pass; use `context.skip()`. A helper that reads `process.env` by default makes tests depend on the shell; pass values explicitly.
- Vitest cannot import files under the OS temp dir; create test dirs under `process.cwd()`. Turn fake timers on only after dynamic imports.
- Plugin events posted with parallel `fetch` arrive out of order; serialize posts.

## Tooling in this environment
- **Shell quoting mangles code.** Heredocs, `sed`, `node -e` and `python -c` lose backslashes, `$1`-style text and quotes, and can write real CR/LF bytes into string literals. Write code with the Write/Edit tools, or put the script in a file and run the file. A JSON or heredoc edit spec turns a `
` meant for a string literal into a real line break (it broke `index.ts` and a test on 2026-11-08); type escapes with the Edit tool.
- **An e2e that creates a worktree must set `code.worktreesRoot` to its temp folder.** Without it the worktree lands in the user's real `~/SessionDeck/worktrees` (D58's first run did; removed by hand).
- **Do not "test" opening a link in an e2e.** A program or script is never run, but it is shown in Explorer: a window pops up on the user's PC. Test the refused cases (missing path) only.
- **A retry loop that spawns git per attempt is slow on Windows.** The worktree name search tried up to 99 names with one `git show-ref` each (5 s, a test timeout); read all branches once (`for-each-ref`) and check the set.
- **Files are CRLF in the working tree.** Multi-line search/replace from a script must use the file's own line ending (`s.includes('\r\n') ? '\r\n' : '\n'`), or the match silently fails. Some files have MIXED endings (`jarvisTools.test.ts`: older lines CRLF, appended blocks LF), so a script must also try the plain LF text when the CRLF version does not match (2026-11-08).

GOAL: Implement the "needs attention" system in src/main/attention/: a local hook server that Claude Code posts to, a per-session attention state, and sound/taskbar-flash notification. Expose it through one facade.
SCOPE (you own only): src/main/attention/**

BACKGROUND: SessionDeck starts each Claude Code session as `claude --settings '<json>'` with env SESSIONDECK_SESSION_ID, SESSIONDECK_PORT, SESSIONDECK_TOKEN. The settings JSON registers Claude Code hooks (Notification = Claude needs permission/input, Stop = Claude finished its turn) whose command POSTs to our local server. This does NOT touch the user's global ~/.claude settings. `claude` 2.1.x is installed here: VERIFY the exact hooks JSON schema and the `--settings` flag against `claude --help` and the official docs (https://docs.claude.com/en/docs/claude-code/hooks) and do a real check that the produced settings JSON is accepted (e.g. run `claude --settings '<json>' --version` or `-p` with a trivial no-cost invocation; do not run long sessions). Claude Code runs hook commands through a shell (on Windows normally Git Bash), so use POSIX `$VAR` expansion and curl; verify `curl` exists on this machine.

SPEC:
HookServer.ts: createHookServer({token:string, isKnownSession:(id:string)=>boolean, onEvent:(e:HookEvent)=>void}) -> {start(): Promise<{port:number}>, stop(): Promise<void>}. node:http bound to 127.0.0.1, port 0 (random). Only `POST /hook`: other path 404, other method 405. Header `x-token` compared with crypto.timingSafeEqual (length-safe) else 401. Body max 4096 bytes (413 beyond, stop reading). JSON {sessionId:string,event:'Notification'|'Stop',message?:string}; invalid JSON/shape 400; unknown session 404; success 204 and calls onEvent. Never log or echo the token. Close all sockets on stop().
claudeSettings.ts: `hookCommand(event: HookEvent['event']): string` (curl -s -m 2 -X POST "http://127.0.0.1:$SESSIONDECK_PORT/hook" -H "x-token: $SESSIONDECK_TOKEN" -H "content-type: application/json" -d '{"sessionId":"'"$SESSIONDECK_SESSION_ID"'","event":"<event>"}' — make sure quoting works in bash AND is correct once embedded in JSON) and `buildClaudeSettings(): string` returning the JSON for `--settings`. No secrets inside the JSON (they come from env). Test: JSON.parse round-trip, and actually execute the command through bash against a real HookServer in a test (skip if bash/curl missing) and assert onEvent fires with the right sessionId.
IdleDetector.ts: fallback when hooks do not fire. createIdleDetector({idleMs=4000, onIdle:(id)=>void, timers?:{set,clear}}) -> {noteOutput(id), noteInput(id), forget(id)}. After output stops for idleMs following output, call onIdle once (not repeatedly until new output). User input cancels the pending idle. Timers injectable for tests.
AttentionManager.ts: holds Map<Id, AttentionReason|null>. raise(id, reason) (ignored if the session is currently focused: deps.isFocused(id) true; ignored if already set with same-or-higher priority; priority permission > done > idle > bell), clear(id), get(id), handleHook(e: HookEvent) (Notification -> 'permission', Stop -> 'done'), forget(id). Emits onChange(cb:(id, reason|null)=>void).
Notifier.ts: createNotifier({beep:()=>void, flash:(on:boolean)=>void, isWindowFocused:()=>boolean, minGapMs=1500, now?}) -> {notify(id, reason), setSoundEnabled(b), stopFlash()}. Sound only if enabled and gap since last beep >= minGapMs; flash only if the window is not focused. (Real impl will use Electron shell.beep and BrowserWindow.flashFrame; do NOT import electron in this module; inject.)
AttentionService.ts (facade, the ONLY thing integration imports): createAttentionService({isKnownSession,isFocused,beep,flash,isWindowFocused,token?:string (default crypto.randomBytes(24).toString('hex'))}) -> { start(): Promise<void>; stop(): Promise<void>; claudeArgs(): string[] (['--settings', json]); envFor(sessionId): Record<string,string> (the three SESSIONDECK_* vars); noteOutput(id); noteInput(id) (also clears attention: the user is interacting); clear(id); get(id); onChange(cb); setSoundEnabled(b); forget(id) }. Wires HookServer -> AttentionManager -> Notifier, and IdleDetector -> raise(id,'idle') (idle fallback enabled by default).
index.ts: export createAttentionService and the types.

EDGE CASES TO TEST: wrong token, missing token, oversized body, invalid JSON, unknown session, wrong method/path, server restart on a new port, stop() twice, two quick events (sound debounce), session focused while event arrives, idle fires once, input cancels idle, priority upgrade (idle -> permission) but not downgrade, clear then raise again.

DONE WHEN: `npx vitest run src/main/attention` passes (including the bash+curl end-to-end test if available); zero type errors in src/main/attention.

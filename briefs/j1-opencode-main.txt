GOAL: Main-process support for running OpenCode (the `opencode` CLI, v1.19) as a session agent next to Claude Code. A session has `agent: 'claude' | 'opencode'` (absent = claude: every existing behaviour and test must stay unchanged).

HOW OPENCODE IS INTEGRATED (decided, verified by the orchestrator):
- Launch: `opencode` in the session cwd. New session: `opencode` plus `--model <provider/model>` only when session.model is non-empty. Resume (wake, reopen, restart, sleep): `opencode -s <opencodeSessionId>` when the id is known; when it is not known start a plain new `opencode` (never `--continue`: it would pick a random conversation). Do NOT pass any Claude flag (`--settings`, `--session-id`, `--resume`, `--dangerously-skip-permissions`) to opencode. A missing `opencode` binary must produce the same kind of visible error the missing `claude` does today (do not crash the app).
- Per-process plugin injection (no files in the user's project or global config): set env OPENCODE_CONFIG_CONTENT to JSON `{"plugin":["file:///C:/abs/path/sessiondeck-opencode-plugin.mjs"],"permission":{"*":"allow"}}` (forward slashes, file:/// URL; "permission *:allow" is the yolo mode: OpenCode sessions never prompt). The plugin file is written by the app at startup into the same directory as the Claude settings file (see claudeSettings.ts writeSettingsFile / attentionDir). Plus the existing env from attention.envFor(sessionId) (SESSIONDECK_SESSION_ID / SESSIONDECK_PORT / SESSIONDECK_TOKEN) which the plugin reads from process.env.
- The plugin (plain ESM JavaScript, a string template in src/main/opencode/pluginSource.ts so it can be unit-tested by `import()`ing the written file with a fake `fetch`): `export const SessionDeckPlugin = async () => ({ event: async ({ event }) => {...} })`. It must NEVER throw and never block (fire-and-forget fetch with a 2 s timeout, errors swallowed because the app may be gone), and do nothing when SESSIONDECK_PORT is missing. Mapping (POST http://127.0.0.1:$PORT/..., header `x-token: $TOKEN`, JSON body, same as the Claude hooks):
  * `session.created` (properties.sessionID or properties.info.id) -> POST /hook/<SESSIONDECK_SESSION_ID>/AgentSession body {"session_id":"<ses_...>"} ONLY for top-level sessions (ignore events whose info.parentID is set: those are sub-agent sessions).
  * `session.status` with properties.status.type === 'busy' -> POST /hook/<id>/UserPromptSubmit (debounce: send only on the idle->busy transition).
  * `session.idle` -> POST /hook/<id>/Stop.
  * `permission.asked` (and `question.asked` if it exists; and also `tool.execute.before` when tool name is `question`) -> POST /hook/<id>/Notification body {"message":"<short text, max 200 chars>"}.
  * `message.updated` for ASSISTANT messages (properties.info.role === 'assistant'): keep per-message cost (info.cost) in a Map keyed by message id (updates repeat), sum them, and POST /statusline/<id> body {"model":{"display_name":"<info.modelID>"},"cost":{"total_cost_usd":<sum>}} (throttle to at most one post per second). No rate_limits: OpenCode has no Claude plan quota.
  Event names above were observed from a real run (session.created, session.updated, session.status busy/idle, session.idle, message.updated, message.part.updated, session.diff). permission.asked / question.asked are from the OpenCode docs: VERIFY them against a REAL run (see VERIFYING).
- HookServer: accept the new event name `AgentSession` on /hook/<id>/AgentSession; its payload `session_id` (validate: string matching /^ses_[A-Za-z0-9]{8,64}$/) becomes HookEvent { sessionId, event: 'AgentSession', message: <that id> }. Everything else about the route (token, size limit, unknown sessions) stays as is. AttentionManager must ignore 'AgentSession' (no sound, no flash).
- sessionController.handleHookEvent: for 'AgentSession' store the id on the session (store method e.g. setOpencodeSessionId, persisted, only when the session's agent is 'opencode' and the value differs) and do nothing else; Notification/Stop/UserPromptSubmit keep working unchanged for opencode sessions (activity, auto status, sound). The Claude-only fallback `shouldFallbackToNew` (NO_CONVERSATION_RE) and `--session-id` bookkeeping/ensureClaudeSessionId must be skipped for opencode sessions.
- Store/validation: Session gets agent/opencodeSessionId/model persisted and loaded (old files without them = claude). asCreateSessionInput accepts `agent` ('claude'|'opencode', else error) and `model` (string, max 200 chars, only [A-Za-z0-9._:/@+-], trimmed; ignored for claude). Settings: accept/persist `agents: { defaultAgent: 'claude'|'opencode', opencodeModel: string (same charset, max 200, may be empty) }` like the other sections.
- startOptions.ts: branch on session.agent. Keep the Claude path byte-for-byte; add an opencode path (command, args, env). PtyManager StartOptions must carry which command to launch (default claude). Reuse the existing WIN_LAUNCHER mechanism for resolving the executable on Windows (npm shims `opencode.cmd` etc.).
